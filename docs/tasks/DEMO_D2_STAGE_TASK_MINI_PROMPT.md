# D2 — короткий prompt для каждого этапа

Этот текст добавляется к карточке конкретного этапа. Карточка задаёт цель,
baseline, точный allowlist и критерии приёмки; этот prompt не заменяет
[Execution Lock](DEMO_D2_EXECUTION_LOCK.md) и
[дорожную карту](DEMO_D2_DELIVERY_ROADMAP.md).

```text
Работай только по утверждённой карточке и указанному этапу действующего roadmap.
Сначала проверь AGENTS.md, baseline, ветку, HEAD, status и разрешённые файлы.
Цель — упрощение архитектуры и устранение причин ошибок общего класса запросов.
Одно решение — один владелец по Target Contract §3: свободный вопрос — модель; проверенная кнопка — сервер; точные данные — код; завершённый разговор — существующая память.
Проверенная кнопка не проходит повторную классификацию. Связная речь не требует дробления на операции. SIM-2/3 проектируются совместно: сохранённый результат → существующая projection, объём вместе с услугой, без новой сводки или вызова.
До архитектурной правки покажи: до → после, владельца, удаляемую зависимость, прежние ветки и поля. Обычную ошибку называй исправлением ошибки.
Не придумывай продуктовые правила; неопределённость покажи на примере до реализации. Внутри согласованных границ технические решения принимай самостоятельно.
Не добавляй без согласования сценарные ветки, эвристики, control fields, параллельную память, model calls или исправление решения другого слоя. Сначала устрани причину в существующем механизме.
Не добавляй семантические regex, ветки под фразы, второй parser и fallback на старый runtime.
При отклонении останови зависимую работу и задай конкретный вопрос в чате. Архитектурные вопросы разбирай с Astra; её заключение не заменяет согласования владельца.
Применяй D2-107–109: уместный обзор без назначения лечения; все финансовые утверждения из утверждённых данных; тема лечения сохраняется через контактное отвлечение в пределах TTL без создания медицинского факта.
Не подгоняй тесты и не ослабляй критерии ради PASS. Проверяй смысл целого диалога, продолжения, состояние, tenant/lead/privacy, точность прайса, подлинность кнопок и медицинские границы.
Этап завершён при правильных диалогах и доказанном удалении зависимости без переноса в другой слой. Подготовленный правильный envelope и зелёные тесты сами по себе этого не доказывают.
Проверяй это на каждом SIM до его закрытия, а не только в REC-5. Для SIM-4 заранее покажи механизм финансового контроля, судьбу неподтверждённой части и сохранение объяснения; согласованный D2-108 не разрешает нового агента или отказа от всего ответа.
До закрытия получи независимый Checker PASS; рубежи текущего roadmap требуют Cursor. Без отдельного разрешения запрещены live, merge, deploy и разрушительные действия.
```
