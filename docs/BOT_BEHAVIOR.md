# Как ведёт себя нынешний demo-бот

Это основной документ для владельца. Техническая архитектура — отдельно;
исторические планы не описывают нынешнее поведение.

| Вопрос или действие человека | Что делает бот |
|---|---|
| «Я боюсь боли», «Какая приживаемость?» | Отвечает обычным текстом по материалам клиники |
| «Nobel ставите?» → «А сколько стоит?» | Использует историю разговора; для цены может вызвать карточку каталога |
| Общий вопрос о цене | Карточка даёт обзор/варианты из каталога; человек выбирает подходящий вариант |
| Конкретная услуга, бренд и объём | Код показывает соответствующую цену и условия из данных клиента |
| «А гарантия?», «Всё включено?» после карточки | Модель отвечает текстом по базе и фактам показанной карточки |
| Вопрос про боль и цену вместе | Возможны полезный текст и ценовая карточка в одном ответе |
| Клик по вкладке/пункту карточки | Код работает с опубликованным вариантом и проверенными данными карточки |
| «Где вы?», «До скольки работаете?», «Есть парковка?» | Отвечает по контактам клиники; может показать отдельный контактный блок |
| «Хочу записаться» или кнопка заявки | Начинает заявку, спрашивает имя и телефон; доступны отмена и продолжение |
| «Покажите ваши работы» | Может предложить галерею, выбрав общий документ результатов; прямой повторный запрос допускает повторный просмотр |
| Клик «Результаты “До и после”» в меню или после услуги | Показывает локальную галерею без вызова модели; фото и описание меняются вместе, кейсы листаются стрелками/свайпом |
| «Я хочу так же» под кейсами | Использует существующую запись; из меню без опубликованной CTA отправляет обычный запрос записи модели, поэтому немедленная форма не гарантируется |
| Неясный вопрос | Может уточнить обычной фразой; особая команда для такого вопроса не нужна |
| Другая тема/услуга | Учитывает новый вопрос вместе с историей; прежняя тема не должна принудительно удерживаться |

Модель — DeepSeek. Ей передаются approved материалы клиента, завершённая история
и показанная карточка. Она пишет объяснения и выбирает запрос карточки; код
показывает цены и интерактивные элементы из каталога. После запроса цены модель
получает фактический результат кода и формирует окончательный текст.

Карточка появляется, когда модель вызвала `show_price`. Иногда полезный ценовой
ответ останется текстом: владелец допускает это. Ни правильный выбор модели,
ни отсутствие ошибок в свободном финансовом тексте не гарантируются.
Показанные кодом суммы и контакты берутся из канонических данных клиента.

Demo-заявка учебная. Приватные имя/телефон заявки не передаются в обычный
контекст модели. Клиенты изолированы, чужие/устаревшие UI-действия не исполняются.
Лимиты demo:30 вызовов модели на сессию,400 в сутки; ценовой второй вызов тоже считается.

На VPS развёрнут demo `e93cb12` (PR #29). В интерфейсе — Inter, интервалы 0,
названия услуг, цены и заголовки карточек имеют жирность 600 на компьютере и телефоне.
У кейсов пока два примера: All-on-4 и циркониевые коронки. Фотографии и четыре
описания хранятся отдельно от базы ответов; общий MD только знакомит с галереей.
Эти JS-описания модель не читает. Каталог врачей в UI и отзывы пока не подключены.

Бот на VPS и локальный тестовый виджет — разные экземпляры запуска;
их настройки и состояние сессий могут различаться.
Текущее состояние, что проверено и что ещё осталось:
[статус](tasks/DEMO_D2_CURRENT_STATUS.md).
Изменения выкладываются через GitHub CI → image → отдельный deploy.
Push рабочей ветки сам по себе VPS не обновляет.

Prompt§61: общие стоматологические объяснения допускают знания модели.
Конкретные факты/обещания о клинике, материалах, услугах, ценах и условиях требуют
подтверждения в данных клиники. Неуказанная подробность требует уточнения,
не означает автоматический отказ в услуге. Длина соразмерна сложности: меньше
повторов/вступлений, сохранить аргументы/условия без лимита абзацев.
Это инструкции модели, не гарантия безошибочного соблюдения.

Prompt§62: общий вопрос — основа из#korotko, если он есть, плюс необходимые факты
и условия. Конкретный вопрос — подходящие разделы, follow-up — выбранный раздел

дополнительные подробности для клика, но не скрывать важное для текущего ответа.
Код показа follow-up не меняется; это инструкция модели, не гарантия отсутствия повторов.


Follow-up §63 (owner GO 2026-10-14): первый элемент `sources` — основной
документ, выбранный моделью по текущему вопросу. Только он задаёт продолжения;
остальные документы дают дополнительные факты и не добавляют/не обнуляют его
ссылки. Все источники проходят проверку. Неверный основной источник не заменяется
следующим. При проверенном клике выбранный документ остаётся владельцем задачи.
Лимит двух ссылок, подавление уже нажатых и границы price UI сохраняются.
Это исправление привязки UI, не новая классификация, память или вызов модели.
Общая тема многотемного ответа определяется прежними правилами, отдельно от UI.
