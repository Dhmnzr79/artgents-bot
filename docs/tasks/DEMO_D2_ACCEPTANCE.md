# D2 — контрольные сценарии и доказательства завершения

Дата: 2026-09-17. **План проверок; результаты PASS здесь не заявляются.**
Связан с [договором](DEMO_D2_TARGET_CONTRACT.md) и [дорожной картой](DEMO_D2_REBUILD_ROADMAP.md).
Все примеры синтетические. Цены/условия ожидаются из fixture конкретной клиники,
а не из придуманных чисел или копии ответа текущего сломанного бота.

## 1. Что именно проверяем

Три слоя доказательств, которые нельзя подменять друг другом:

1. Малые offline проверки структуры/применимости/состояния — только где нужны.
2. Offline пользовательский сценарий через `/ask` и `/ask/stream`, реальные
   parser → resolver → plan → renderer → session/UI. Подменён только внешний
   provider и внешняя доставка заявки; сеть к провайдеру заблокирована.
3. Отдельно разрешённый live-набор проверяет свободный текст и выбранные источники.
   Он не заменяет детерминированную проверку tenant/цен/памяти.

Для каждого диалога проверяются: полнота частей, утверждения и источники, суммы и
единицы/условия, видимые кнопки/CTA и их следующий ход, память после ответа,
количество provider calls и внешних effects. Не только status 200/route/helper.
Текстовые связки не требуют точного snapshot; критические значения и authored
формулировки требуют. Не делать ожидаемый результат вызовом того же selector.

## 4. Технические проверки полной цепочки

| ID | Внедряемая ситуация | Что доказываем |
|---|---|---|
| C01 | Malformed JSON, truncated envelope, unknown enum/ID, nullable разрешённые поля | Предсказуемые ошибки без второго LLM/старого fallback; общий вопрос не требует exact service ID |
| C02 | Корректная часть + сломанная независимая часть; сломанная короткая/полная форма акции; прямой запрос только акции | Основное сохраняется где допустимо; optional commercial failure не скрывает цену; обязательный прямой promo-ответ не исчезает и не подменяется короткой формой с ложным status success |
| C03 | Чужая сумма/условие в prose, противоречащая гарантия; отсутствие безопасного фрагмента | Обнаруженное нарушение не остаётся рядом с правильной карточкой; fallback по T3; отдельный live тест для непойманной семантики |
| C04 | Существующий чужой tenant ID/source/UI; не показанная кнопка; устаревший request/ref | Никакой утечки, действия или side effect; source из разрешённого input snapshot |
| C05 | Repeat request, другой payload с тем же ID, параллельные ходы, разрыв SSE и replay | Один сохранённый результат/дельта/lead; конфликт отклоняется; нет повторного LLM на завершённом replay |
| C06 | Сбой до/после фиксации результата; неопределённый исход отправки заявки | Нет фиктивного показа или слепой повторной отправки; явная обработка pending/failed/unknown |
| C07 | Старая обычная сессия, активная заявка, legacy кнопка, новый/старый runtime с новым хранилищем | T6; privacy сохранена; откат не ломает вход/lead, несовместимость блокирует release |
| C08 | Запрет всех заменяемых legacy функций; статические import/dependency проверки | A/B сценарии проходят реальные endpoint без вызова запрещённых функций; перечень символов фиксируется в S1 |
| C09 | Каталог меняется после freeze; сравнение /ask и /ask/stream | Текст/UI/trace/memory относятся к одному плану и snapshot; после freeze нет повторного отбора |
| C10 | Запрет сетевого транспорта в offline; счётчик call budget; PII name/phone/mixed note | Ноль реальных вызовов offline; обычный live максимум 1; персональные данные не уходят из lead/privacy границы |

C08 не является математическим доказательством всех возможных входов. Вместе с
удалением старого кода, проверкой зависимостей и отсутствием post-render mutations
это конкретное доказательство архитектурного ограничения на поддержанных маршрутах.
Regex допустим для формата/PII, но не для второго толкования вопроса.

## 6. Исходные метрики и live-план

Существующий отчёт `../audits/DEMO_D2_LATENCY_BASELINE.md`: 12 вызовов на базе
`95799f7`, qwen3.8-flash/prompt v16, все с прогретым cache. Медиана сервера 6,297 с
включает ошибки; это не обещание 6–8 с, не browser latency и не надёжный p95.
Известно: оба broad implantation ответа — технические отказы; один warranty
противоречив; mixed непостоянен. Никакой новой baseline-прогонки в этом этапе.

До реализации сохранить версию модели/prompt/data, размер контекста, output cap,
существующие failing cases и ожидаемое исправленное поведение. Согласованный
ориентир — медиана полного корректного ответа до 7 секунд в сопоставимых прогретых
условиях; каждый ответ дольше 10 секунд разбирается отдельно. Это не обещание
скорости заранее и не абсолютный максимум. До live отдельно согласовать бюджет
вызовов/стоимости. Сравнивать отдельно успешные ответы и ошибки,
provider time, серверный итог, browser first useful paint, число вызовов,
input/output/cache tokens. Cold/warm и последовательные/конкурентные запросы не
смешивать в одну «среднюю». Не объявлять p95 достоверным на малой выборке.

Предложение экономного live checkpoint: первоначальные 6 вопросов baseline по
одному разу + многоходовые A01/A07/A10 и одна проверка A06. Точный перечень ходов
и жёсткий бюджет утверждаются до запуска; сейчас budget = 0. После провала
повторять затронутые случаи в отдельном согласованном бюджете, не весь набор.
Перед итоговым включением покрыть все смысловые семьи A/B, при необходимости
параметрами, с перечнем непроверенных случаев в отчёте. Нет требования live
повторять технические crash/tenant/transport инъекции C.

## 7. Семь критериев завершения D2

1. Оба endpoint и виджет используют один финальный договор; нет post-plan
   переопределения смысла/цен/UI или запасного legacy runtime.
2. Старые смысловые функции удалены либо недоступны с доказательством C08;
   временные обходы и отменённые сценарии отсутствуют в конечном дереве.
3. A01–A12 и все применимые B/C проходят end-to-end offline; critical assertions
   не ослаблены, известных незакрытых провалов базовых сценариев нет.
4. Каждый показанный факт/цена/политика/UI имеет проверенную привязку к текущей
   клинике; нет выдуманных сумм, подменных услуг и сохранённых известных нарушений.
5. Память, повторная доставка, tenant isolation, lead/privacy и старые сессии
   проходят проверки; внешняя доставка не выдаёт недоказанное exactly-once.
6. Отдельно разрешённый live-набор и независимый Checker пройдены; качество,
   стоимость и задержка измерены и укладываются в заранее согласованные критерии.
7. CI, актуальные документы и репетиция совместимого rollback готовы; commit,
   push/PR и ограничения явно отражены. «Release-ready» и «развёрнуто» различаются;
   deploy требует отдельного разрешения и не совершается ради отметки в документе.
