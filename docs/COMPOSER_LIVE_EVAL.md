# Composer Live Eval — гейт перед включением COMPOSER_ON

Ручной прогон композера на живых составных вопросах. Цель — решить: **включать ли `COMPOSER_ON`
на составных вопросах, дорабатывать тон, или пока не включать.**
Проектные детали композера: `COMPOSER_ROADMAP.md` (Фазы 2–3).

Это НЕ автоматический golden. Часть проверок (цифры, откаты, маршрут) — по телеметрии,
часть (тон, склейка, хеджи) — глазами. Так и задумано: тон судит человек.

---

## Как запускать

1. `COMPOSER_ON=1`, поднять `app.py` (или как обычно).
2. Каждый вопрос — в **свежей сессии** (кроме кейсов на перенос темы, если добавишь).
3. Для каждого ответа записать из `meta`:
   - `answer_path` — `composer` или `single_source`;
   - `numeric_fact_gate.action` — должно быть `pass` (не `remove_fact` / `blocked`);
   - `composer_skip_reason` — если был откат (`single_aspect` / `forbidden_claim`);
   - `forbidden_claim_hits` — должно быть пусто.
4. Прочитать сам текст ответа и оценить по чек-листу C1–C6 ниже.

## Чек-лист по каждому ответу композера (C1–C6)

**Жёсткие (нарушение = FAIL, не включать):**
- **C1. Числа целы.** Каждая сумма, «от»/единица («за челюсть»), список «что входит» —
  дословно из pricebook. `numeric_fact_gate.action == pass`. Ни одной изменённой/выдуманной цифры.
- **C2. Нет запретных обещаний.** `forbidden_claim_hits` пуст; в тексте нет «безболезненно»,
  «гарантируем результат», «приживётся на 100%» и т.п.
- **C3. Оба аспекта отвечены.** Ответ реально закрывает **каждый** аспект вопроса. Потерян аспект = FAIL
  (иначе теряется весь смысл композера).

**Мягкие (судит человек; «не хуже старого + заметно живее»):**
- **C4. Хеджи сохранены.** «обычно», «зависит», «после осмотра», «индивидуально» на месте;
  нет категоричных мед-утверждений.
- **C5. Тон и склейка.** Читается как один живой ответ голосом клиники, а не сшитые куски. Оценка 1–5.
- **C6. Маршрут верный.** `answer_path == composer` на составных; `single_source` на контроле (Группа D).

## Пороги «включать / нет»

| Критерий | Порог для включения | Почему |
|----------|---------------------|--------|
| **C1 числа** | **100%** (0 ошибок на Группах A+B) | деньги/медицина — не подлежит компромиссу |
| **C2 обещания** | **100%** чисто в тексте | откаты допустимы, но обещание в тексте — нет |
| **C3 оба аспекта** | **≥ 90%** | смысл композера — покрыть весь вопрос |
| **C4/C5 хеджи+тон** | **явно живее старого, не хуже по безопасности** | это судит маркетолог (ты) |
| **Частота отката** | если > ~30% составных откатываются — **не включать, разбираться** | значит композер ещё сырой или материал не резолвится |

**Решение:**
- Все жёсткие пороги взяты + тон нравится → **включить `COMPOSER_ON` на составных.**
- Числа плывут ИЛИ обещания проходят → **не включать**, чинить (промпт/гейт).
- Тон слабый, но безопасность ок → **доработать промпт композера**, прогнать снова.

## Что означает каждый провал

| Симптом | Причина | Куда копать |
|---------|---------|-------------|
| C1: цифра изменена, gate = `remove_fact`/`blocked` | Qwen не воспроизвёл блок дословно | усилить правило «ДОСЛОВНО» в промпте; при частом — вернуть цену детерминированной вставкой |
| C2: `forbidden_claim_hits` часто | Qwen склонен обещать | расширить blocklist (осторожно) / усилить промпт |
| C3: аспект потерян | материал не резолвился (Группа C) или Qwen пропустил | расширить content-ref покрытие (не только имплантация); проверить порядок карточек |
| C4: хеджи роняются часто | подтверждает необходимость 3b-ii (активный гейт хеджей) | вернуться к отложенному 3b-ii |
| Откаты часты на Группе C | узкий `_TOPIC_CONTENT_REF` | обобщить резолв контент-ref из каталога |

## Замечание про Группу C (материализация контента)

Сейчас `core/answer_packet._service_content_ref` знает контент-ref только для `implantation`
(pain, duration). Для отбеливания/виниров/удаления аспектный контент не резолвится → карточка
пропускается. Это **известный узкий край**, а не регрессия: happy-path (имплантация) полон,
не-имплантация вскроет, где расширять покрытие. По итогам прогона — отдельная задача
«обобщить content-ref из каталога», если не-имплантация важна для запуска.
