# TASK — Close Price and Service Product Rules

Один docs-only checkpoint. Зафиксировать последние согласованные решения по приоритетам, типам цен, отсутствующей публичной цене, протоколам и брендам до schema/runtime реализации.

Общие правила: `.cursor/rules/00-guardrails.mdc`, `REVIEW_CHECKLIST.md`.

## Цель

Обновить `drafts/PRICE_RESPONSE_RULES_DRAFT.md`, чтобы продуктовый блок услуг и цен имел однозначные правила и честно отделял будущую target-модель от текущего runtime. Синхронизировать раздел открытых решений в `docs/SERVICE_SELECTION_CONTEXTS.md`, чтобы уже согласованные место стратегии и no-price fallback не оставались там открытыми.

Документ не передаёт authority, не меняет клиентские данные, Pricebook, код, prompts или UI.

## Согласованные решения

### 1. Стратегия клиники

- target owner — отдельный `clients/<client_id>/clinic_strategy.yaml`;
- в нём только `max_options`, приоритет услуг, редкие context overrides и порядок offers/брендов внутри услуги;
- активность и применимость остаются в каталоге, суммы и billing unit — в Pricebook;
- promo, CTA и маркетинговые тексты в стратегию цен не входят;
- explicit service/brand пациента важнее приоритета;
- приоритет не может добавить отсутствующую или неприменимую услугу;
- общий ценовой обзор сначала обеспечивает согласованное покрытие масштабов, затем применяет приоритет внутри масштаба.

### 2. Услуга без публичной цены

- информационный вопрос получает обычный ответ по KB;
- ценовой вопрос получает утверждённую клиникой no-public-price формулировку и одну CTA по будущей marketing policy;
- похожая цена, вычисленная сумма и цена компонента вместо услуги запрещены;
- другая применимая услуга с подтверждённой ценой может быть показана только как отдельно названная альтернатива, а не замена отсутствующей цены.

### 3. Типы цен

- фиксированная;
- «от»;
- диапазон;
- публичной цены нет / по запросу;
- любая числовая цена обязана иметь точную единицу расчёта;
- schema naming и migration current `fixed/from` выбираются позднее, product semantics фиксируются сейчас.

### 4. Протоколы

- протоколы берутся из активного каталога по family/roles, а не из Pricebook groups;
- связанные процедуры и этапы не выдаются за протоколы;
- общий вопрос получает компактный список, при необходимости с отдельной группой сложных протоколов;
- текст может перечислить весь разумно короткий активный список, кнопки ограничены 2–3 приоритетными протоколами и одной CTA;
- цена добавляется только при ценовом акценте;
- нажатие протокола ведёт к подробному ответу по его KB-документу.

### 5. Бренды

- brand dictionary отвечает за canonical name, country и aliases; Pricebook offer — за связь бренда с услугой и ценой; KB — за утверждённые описания/сравнения;
- перечисляются только бренды, реально связанные с активными offers клиники, включая offers без публичной числовой цены;
- запрос по стране использует точное поле country, а не догадку по названию;
- общий brand-price вопрос сразу показывает короткий обзор 2–3 сопоставимых offers с точными service/unit, а не прячет все цены за уточнением;
- известный patient scope фильтрует offers; при неизвестном сохраняется покрытие разных масштабов;
- сравнение «дешевле» допустимо только для одной услуги, одинаковой единицы и сопоставимого состава;
- «лучше» отвечает только по утверждённому KB-сравнению; цена, страна и clinic priority не становятся медицинским преимуществом;
- brand buttons допустимы в явном brand-list сценарии; service/protocol buttons — в protocol/service сценарии;
- отдельная кнопка «Показать цены» не добавляется.
